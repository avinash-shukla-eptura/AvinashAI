## Root Cause (Observed in Code)
`MeetingUpsertEntity` implements `ITableEntity` (Azure.Data.Tables SDK). Three fields are typed
as `DateTime`/`DateTime?` — `DateTimeFrom`, `DateTimeTo`, `EnqueuedTimeUtc` — while the
Azure.Data.Tables SDK internally requires `DateTimeOffset` for date serialization. When
`TableClient.UpsertEntityAsync` serializes the entity, it boxes the `DateTime` as `object` and
attempts an unbox-cast to `DateTimeOffset`, which throws `InvalidCastException`. The entity's
`Timestamp` property is already `DateTimeOffset?` (correct), demonstrating the team knows the
required type. The fix is to change the three `DateTime`/`DateTime?` fields in
`MeetingUpsertEntity` to `DateTimeOffset`/`DateTimeOffset?` with appropriate UTC-preserving
conversions.
