# Plan: AID v1 portable skills (v0.10.2)

**Repo:** `eptura/aid-protocol`, local clone `D:\DeviceHubEptura\aid-protocol`, base `origin/main` @ `7182de3`.
Approach 2 (full neutral layout, `2026-10-30-aid-tool-agnostic-v1-plan.md`) is deferred; the user will
re-plan it later on top of this release. No no-AI bootstrap script (out of scope).

**Follow-up decision (2026-11-17, user):** ship this v0.10.2 first, then do Approach A: every AID-owned
file lives in one folder, `.aid/` (`.aid/skills/`, `.aid/hooks/`, `.aid/bin/`, `.aid/rules/`,
`.aid/mcp.json`); tool folders (`.claude/`, `.cursor/`, `.vscode/`, `.github/hooks/`, `CLAUDE.md`, root
MCP files) are generated by `.aid/bin/aid-sync.{sh,ps1}` and gitignored; only `.aid/` + a thin root
`AGENTS.md` are committed. Rejected: links instead of copies (break on Windows), AGENTS.md-only pointer
(no slash commands, no gate). That plan revises `2026-10-30-aid-tool-agnostic-v1-plan.md`
(`.agents/skills` -> `.aid/skills`) and must start from the v0.10.2 tag.

## Requirement
- **What:** after installing AID on a machine with no Claude Code, any agent can run `/aid-init`,
  `/aid-seed` and the RIPER skills; the installer needs no `claude` CLI on Windows or Unix.
- **Who:** engineers on VS Code/Copilot, Cursor, Codex and similar; existing 0.10.1 repos.
- **Why:** on a Claude-less Windows machine the agent tried `aid init` as a shell command and failed.
  Root causes (see `2026-11-17-aid-init-without-claude.md`): all 16 skills have `name:` != folder
  (VS Code/Cursor drop them), bash installer skips skills+hooks without `claude` (build.sh:402),
  skills hard-code `bash .claude/hooks/scripts/riper-state.sh` (23 refs), and AGENTS.md never tells
  an agent where the skill files are.
- **Done when:** fresh Windows install with no `claude` -> `/aid-init` listed in VS Code Copilot and
  Cursor; AGENTS.md lets any file-reading agent run a skill; RIPER gate still enforced in Claude Code
  and Cursor; CI green.

## Approach Chosen
Keep every installed path. Fix skill names, install skills/hooks regardless of `claude`, make the
state-helper call OS-aware, add a skill-location section to AGENTS.md (also upserted into existing
AGENTS.md files), fix "Next steps" wording, add CI guards, release 0.10.2.

## Alternatives Considered
- Approach 2 - full neutral layout v0.11.0: deferred (40 tasks, migration risk); user will plan later.
- Approach 3 - staged (this, then 2): effectively what the user chose by deferring Approach 2.

## Key Decisions
- `name:` == folder (`aid-plan`, not `plan`). Claude Code's bare `/plan`-style alias disappears;
  AGENTS.md already routes bare RIPER verbs to `/aid-*`, so no behaviour loss (and `/plan` collides
  with Claude's built-in anyway).
- State helper written as a named step, `riper-state <args>`, defined once per skill:
  Windows -> `pwsh -NoProfile -File .claude/hooks/scripts/riper-state.ps1`, else
  `bash .claude/hooks/scripts/riper-state.sh`. Missing helper -> continue (existing fallback text).
- AGENTS.md gets a `## AID Skills` section; installers append it to an existing AGENTS.md only if
  that heading is absent (idempotent, never rewrites the user's file).
- `claude mcp add` stays gated on the `claude` CLI; `.mcp.json`/`.cursor/mcp.json`/`.vscode/mcp.json`
  are already written unconditionally.
- No Copilot hard gate in this release (needs Approach 2's adapter); AGENTS.md already says
  "elsewhere honour it by discipline".

## Architecture Impact
- No layout change, no new files in installed repos beyond the AGENTS.md section.
- `spec`/README: one paragraph on cross-tool use. Nothing in AvinashAI's ARCHITECTURE.md changes.

## Testing Strategy
- **Unit/CI:** new ci.yml steps: skill `name` == folder for all `plugin/skills/*`; no bare
  `bash .claude/hooks/scripts/riper-state.sh` in skills; bash installer run with `claude` absent from
  PATH still installs 16 skills + `.claude/settings.json` hooks; AGENTS.md contains `## AID Skills`
  exactly once after two installs (fresh and pre-existing AGENTS.md).
- **Integration:** existing CI (embed drift, provenance GC, hook merge, RIPER gate, Windows
  install.ps1 e2e, gate parity) must stay green.
- **Manual (Windows, no claude on PATH):** run dist/install.ps1 in a scratch repo; open in VS Code
  Copilot -> `/aid-init` listed and runs; open in Cursor -> `/aid-plan` listed, edit blocked in PLAN;
  Claude Code (another machine) -> `/aid-plan` still works.
- **Regression risk:** `test/test-install.sh` Test 6 assumes skills skipped without claude - update it.
  Provenance hashes change for all 16 skills (expected: reinstall updates them).

## Rollback Plan
- **How to undo:** revert the PR / don't publish the v0.10.2 release; 0.10.1 assets remain.
- **Data safety:** nothing destructive; AGENTS.md change is append-only; skill files are AID-owned.
- **Blast radius:** repos that installed 0.10.2 see `/aid-*` names only (no bare aliases); re-running
  0.10.1 installer restores old skills.
- **Point of no return:** none.

## Risk Assessment
| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| Cursor/VS Code version doesn't read `.claude/skills` | Med | Med | AGENTS.md `## AID Skills` path fallback; manual check records versions |
| Agent misreads the `riper-state` shorthand | Low | Low | Exact commands in the definition line; helper absence already tolerated |
| AGENTS.md upsert duplicates section | Low | Low | heading-presence check + CI assertion |
| Renamed `name:` breaks provenance GC / drift detection | Low | Med | existing CI GC + embed-drift steps; manual reinstall over 0.10.1 |
| Version strings missed | Low | Low | existing "Version consistency" CI step |
